The headline

Critical · still live

ShotTx reports CounterSatisfiable for problems that are theorems. Five such answers appear in the sweep, spanning four distinct conjectures. The demodulation fix in 7736c67 did not close them: I re-ran all five against the current working tree and every one still returns CounterSatisfiable.

The most serious is SYO040^2 — the Kaminski equation — which fails under the baseline configuration, i.e. stock %Parameters{}, in about 100 ms.

Three structural observations shape everything below.

  • The refutation side is clean. Across all 81 744 rows there is not one bogus Theorem. Every violation is a bogus countermodel. Whatever is wrong lives entirely in the SAT-exit path, not in the tableau closure rules.
  • No countermodel was ever checked. Of the 991 csa answers in the sweep, zero had csp_calls > 0 — while 39 254 rows overall did call the CSP solver during closure. The countermodel verdict rests entirely on one syntactic predicate, Branch.model_certain?/2, and is never validated by anything.
  • All four conjectures are Boolean-extensionality problems. They are theorems only because $o has exactly two elements. SYO017^1's own TPTP header spells out the failure mode: “Without Boolean extensionality : CounterSatisfiable.” That is precisely the answer ShotTx gives.

Compounding · the scorer under-reports

TptpRunner.score/2 (tptp_runner.ex:662) only scores Theorem and CounterSatisfiable. A csa against an Unsatisfiable or ContradictoryAxioms problem, or a thm against a Satisfiable one, all record as na rather than as violations. I re-scored the sweep under the full SZS table: no additional violations surfaced, and there were no claims at all on Unknown/Open problems — so five is the true count. But the truth table should be widened before the next sweep, or a future regression in those classes will be invisible.

Root cause 1 — distinct terms are not distinct elements

model_certain?/2 admits a branch as a countermodel when every same-head, opposite-polarity literal pair is separated: some argument position holds two terms a free term model may read as distinct domain elements. That test delegates to base_typed_rigid?/1, whose docstring promises “distinct rigid constants at a base type.” The implementation does not check arity:

defp base_typed_rigid?(term_id) do
  term = TF.get_term!(term_id)

  match?(%Type{goal: goal, args: []} when goal != :o, term.type) and
    term.bvars == [] and term.head.kind == :co and MapSet.size(term.fvars) == 0
end                                     # branch.ex:291 — no `term.args == []`

So h ⊤ and h ⊥ qualify. They are closed, rigid-headed and $i-typed — and syntactically distinct, so the predicate rules that a model may keep them apart. No model need do so. h is not injective, and its argument type has two elements.

What the prover actually handed back

After unfolding: P(h ⊤) holds, and P(h ⊥), P(h (f ⊥)), P(h (f (f ⊤))) all fail. Now push it through a two-element $o. From ¬P(h (f ⊥)), f ⊥ cannot be ⊤, so f ⊥ = ⊥. From ¬P(h (f (f ⊤))), f (f ⊤) cannot be ⊤ either, which with f ⊥ = ⊥ forces f ⊤ = ⊥. So f ≡ λ_.⊥ — and under that reading both sides of the conjecture reduce to h ⊥. The countermodel satisfies the conjecture it was supposed to refute. The predicate accepted it because it counted h ⊤, h ⊥, h (f ⊥) and h (f (f ⊤)) as four separate elements of $i, when h ranges over at most two.

Fix, tested

Separation has to recurse. Distinct rigid constants separate outright; equal heads separate only through an argument pair that separates in turn — which $o-typed arguments never do.

+ defp rigid_terms_distinct?(s, t, equations) do
+   term_s = TF.get_term!(s)
+   term_t = TF.get_term!(t)
+
+   cond do
+     term_s.head != term_t.head -> true
+     length(term_s.args) != length(term_t.args) -> false
+     true -> Enum.any?(Enum.zip(term_s.args, term_t.args), &distinguishable?(&1, equations))
+   end
+ end
Verified · costs nothing
  • All five violations become GaveUp.
  • All 61 / 61 legitimate CounterSatisfiable answers survive — re-run individually at the same 2 s budget.
  • mix test: 169 passed, 12 excluded.
  • 60-problem Theorem sample: 58 unchanged, 2 timeouts — and both of those also time out on unpatched HEAD, so neither is a regression.

The naïve version of this fix — just adding term.args == [] — also closes all five, but costs 18 of the 61 real countermodels. The recursive form is strictly better.

The change is sitting uncommitted in the working tree (lib/shot_tx/prover/branch.ex, +19/−1). It is yours to keep or drop — but read the next section first, because it is not sufficient.

Root cause 2 — pairwise separation is not satisfiability

Critical · survives the fix

With the recursion in place, SYO041^2 still returns CounterSatisfiable at default parameters — 2 of 8 runs with the full worker pool, 3 of 4 in serial mode. There is a second, independent unsound path.

SYO041^2 is entirely Boolean: f, g : $o > $o and every variable is $o-typed, so no $i term ever reaches distinguishable?. Separation here is decided by the head clause — different rigid heads, therefore separated:

CSA
[C[W8FGZ] <- ⊤, C[TIM87] <- ⊤, C[QALYF] <- ⊤, C[27H6QF] <- ⊤,
 C[6WCN6] <- ⊤, C[1O1MKG] <- ⊤, C[PCVG4] <- ⊤, y <- ⊥]
Model: ¬y, C[6WCN6], ¬(g C[6WCN6]), ¬(g (f C[6WCN6])), ¬(f (f (f C[6WCN6])))

Those five literals are pairwise non-complementary, and as an isolated Boolean assignment they are satisfiable (f ≡ g ≡ λ_.⊥ works). But they are not the branch. The negated conjecture's other conjuncts — x ≠ y, g x = y, g y = x — were consumed into abbreviation constants earlier in the derivation and are simply absent from the literal set the predicate inspects.

This is the general defect, and root cause 1 is a special case of it: model_certain?/2 is a pairwise syntactic non-complementarity test being used as a satisfiability test. It does not enforce congruence, it does not know that $o has two elements, it does not see the constraints already discharged into branch.defs, and it never consults the unifier. Two prior patches in this same file — the unfold_equations/4 comment at branch.ex:697 and the demodulate-on-ingest comment at branch.ex:689 — each fixed one more way for an unsound CounterSatisfiable to slip through. This is the third and fourth. They will keep coming until the verdict is checked rather than inferred.

Related · nondeterminism

SYO017^1 returned CounterSatisfiable, GaveUp, Theorem, GaveUp, Theorem across five identical invocations. SYO041^2 and SYO500^1 vary the same way, and SYO041^2 keeps varying at worker_pool_size: 1 — so worker scheduling is not the whole story. A prover that answers differently run to run cannot be trusted on the runs where it happens to be right, and it makes the ablation deltas below noisier than their precision suggests.

Proof reconstruction was hiding violations

ShotTx.Proof.interior_event/2 has no clause for {:instantiate, …} trace entries, so any refutation whose proof tree contains one raises and the whole result is discarded as prover_error. That happened 57 times across the sweep — around four per configuration — and the inspected payload shows an unevaluated #Stream<…> leaking into the trace.

The consequence is worse than lost results. Two of baseline's five prover_error rows — SYO041^2 and SYO500^1 — now return an unsound csa on HEAD instead of crashing. The crash was masking the bug. Fixing proof reconstruction made the observable soundness picture worse, not better, which means the sweep's count of five is a floor on HEAD, not a ceiling.

What the components are worth

  • The contradiction agent is the prover. Removing it costs 365 of 746 solves. Nothing else is within an order of magnitude. Global closure via the CSP, not local ground closure, is doing the work.
  • Iterative deepening (−94) and demodulation (−41) are the next real contributors. Both earn their keep.
  • Eager definition unfolding is the one clear win (+48) and by far the largest source of uniquely-solved problems (44). Discount it somewhat: 10 of its 72 gains overran the 2 s budget, some as far as 6 s. The gain is real but smaller than +48.
  • beta_variant is a net negative (+22 when removed) at this budget. Worth re-examining — it costs 42 problems to buy 20.
  • Four components are indistinguishable from noise: primitive substitution (−1), suggestions (−1), parallelism (−2) and instance-based gamma (−3). Each still trades 16–36 problems in both directions, so they are doing something — just nothing that nets out. serial matching a 16-worker pool on solved count is the one to look at hardest: the parallel search is buying no coverage, only latency.
  • Both tuning sweeps say “leave it alone.” Gamma limits 3 and 5 are worse than 1 (−21, −25); prim-subst batch 4/8/16 spans 3 problems total. Neither knob is worth exposing as a tuning surface.

What to do

  1. Stop emitting CounterSatisfiable until it is checked. Gate the SZS status behind an actual model check and report GaveUp otherwise. A prover that never claims countermodels is weaker; one that claims them wrongly is unusable. This is the only change that makes today's binary trustworthy.
  2. Take the distinguishable? recursion. It is in the working tree, closes root cause 1, and costs none of the 61 real countermodels.
  3. Build the real check for root cause 2. Unfold definitions, ground the $o-typed subterms over {⊤, ⊥}, and test the literal conjunction with the ROBDD already in ShotTx.Util.PropSimplify. All four failing conjectures live in a decidable fragment — SYO040^2's own header says so — so this is a decision procedure for exactly the family that is breaking, not a heuristic.
  4. Add an {:instantiate, …} clause to Proof.interior_event/2. 57 discarded results, and it was concealing two violations.
  5. Pin the five as regression tests. They run in under 150 ms each and would have caught both root causes.
  6. Widen TptpRunner.score/2 to the full SZS truth table so the classes it currently scores na cannot regress unseen.
  7. Chase the nondeterminism. It persists at worker_pool_size: 1, so it is not scheduling alone. Until it is gone, every delta in the table above carries unquantified run-to-run noise.
  8. Then re-run the sweep with a hard-enforced timeout and a working parser. The current numbers rank the components correctly, but the absolute figures rest on a 16.6 % unparsed corpus and a soft budget that 45 solves exceeded.
